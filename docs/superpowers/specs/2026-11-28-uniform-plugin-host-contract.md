# 插件宿主能力一致性核对与改造契约

日期：2026-11-28
状态：用户已批准并完成实现与验证。下方“改造前实际行为”为历史问题；实际 API、阶段边界与验证记录见 docs/plugins/middleware-api.md 和对应实施计划。

## 改造前实际行为

- QuickJS 脚本共享 __host.compressBrotli、fetchAsDataUrl、log；log 目前只是空实现。没有账号读写 API，也没有通用重试/续写动作 API。
- recovery.accountHealth.js 返回策略字段，实际 v2 内置策略通过 builtin_plugins.rs 的 ID 分支直接解析，并非完整地执行脚本逻辑。仓储读取有效策略与 health_allows，然后使用内部事务/SQL 修改账号或模型状态。
- failure_rules.rs 硬编码 recovery.retry/accountHealth，route_proxy_service.rs 硬编码恢复、清理、图片与推理插件 ID；流式续写由内部 StreamPump 和 continuation 实现。
- onEvent 被注册但未接入生产调度。第三方 pack 固定为 perAttempt/response 阶段，无法通过清单声明内置插件的全部阶段。
- 第三方贡献清单只提供 middleware.js 文件名，账号 UI 为第三方强制填入 lane=both、kind=transform、空 config_fields。
- 因此当前实现有共享脚本运行器和部分通用变换，但不是完整对等的插件系统。

## 统一原则

每个插件使用相同版本的生命周期、上下文、配置 schema 和宿主动作 API。内置仅表示随应用分发，不提供私有处理通道。阶段有效性、资源上限和账号作用域对内置与第三方统一适用。

业务规则属于插件：匹配哪些错误、何时重试/续写、失败计数条件、冷却策略、需要删除哪些请求字段。
宿主执行器负责：实际发送请求、SSE 帧/输出连续性、账号事务与并发控制、取消与预算上限、作用域验证、诊断日志。
复杂续写重建可以是所有插件可调用的通用能力，不要求每个插件重新实现协议桥。

## 设计契约

- hooks：onRequest、onResponseHeaders、onResponse、onStreamEvent、onFailure、onComplete。
- ctx：当前账号/模型只读状态、当前阶段、attemptId、requestId、已提交输出状态、已用预算、规范化错误事实、插件配置。
- requests：修改当前请求 body/headers 的标准返回值；响应/流事件变换使用相同契约。
- accounts：获取作用域内账号状态，记录失败/成功、设置冷却、更新允许的运行状态/标签；所有插件均可使用同样的命令集合。
- retry：重试当前账号、切换候选账号；共享有限预算与取消机制。
- streams：在可续接阶段申请继续当前响应；通用执行器重建历史并拼接输出。
- storage：插件命名空间状态；持久计数须使用原子更新，不能读后覆盖造成并发丢失。
- diagnostics：记录命中规则、发起动作、执行/拒绝原因，真实可读取。

动作可以用公开 SDK 方法构造，hook 返回结构化 actions；宿主在 hook 成功结束后统一验证执行。JS 调用结果与持久化结果区分，动作执行结果可供后续事件观察；不能在每帧 hook 中直接运行任意 SQL。

## 账号故障插件的示意流程

1. 宿主发出包含 status/code/type/message 的 onFailure 事件。
2. 插件匹配自己保存的规则，返回记录失败或设置冷却/异常状态的动作。
3. 通用动作执行器根据当前调用绑定的账号/模型作用域执行事务，返回结果，并通知账号 UI 刷新。
4. SDK 不提供以任意账号 ID 越过当前作用域的隐式权限。需要跨账号操作的合法能力必须公开定义、对所有插件使用同一规则。
5. 同一 attempt 的重复事件不得导致失败计数重复增加。动作带幂等键；账号用户手动暂停/撤销状态不被插件的旧快照覆盖。

## 统一清单与界面

内置和第三方共同声明 api_version、hooks/stages、默认配置、配置字段/规则编辑 schema、功能说明、报错示例与所需能力。UI 完全按 descriptor 渲染，不能出现 if id == builtin.recovery.xxx 才显示规则编辑器。

SDK 方法的可用性由阶段与声明能力决定，不由 builtin/pack 身份决定。所有插件可以声明同一组能力；没有某内置 ID 专属的动作。

## 验收标准

1. 把账号故障处理脚本复制为一个随机 ID 的第三方包，不改宿主代码，也能记录失败、冷却、标记异常，并在 UI 编辑同样的配置。
2. 将失败重试/续写插件改成随机 ID，仍能收到相同事件并驱动相同宿主动作。
3. 安装外部包的真实加载路径测试，不能仅直接调用 JS helper；覆盖 ID 解析与命名空间。
4. 同样的配置、默认值、作用域、预算和故障结果，对内置/第三方一致。
5. 执行器及账号仓储不出现业务插件 ID 判断；允许 ID 出现在注册目录、默认预装列表、迁移和测试中。
6. 关闭/移除后事件不再送达、未提交动作不执行；已启动操作遵守统一取消语义。
7. 并发失败、重复事件、脚本超时/异常、部分动作失败有确定行为和诊断，不能执行一半又不记账。
8. 通过运行时动作与真实账号仓储的集成测试，再声称插件系统已完成对等化。
