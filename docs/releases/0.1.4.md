AI Switch · AI本地网关 `v0.1.4`。继续提供 **Windows x64 / Linux x64 / macOS ARM64** 三个分平台安装包，每个包只包含该平台自己的 native 库。默认地址仍是 `http://127.0.0.1:29527`，从 `0.1.3` 升级不需要改客户端配置。

## 修复：多资源 Azure 中转的「跨资源」报错

一些 Azure Responses 中转在池内轮换多个资源却没有会话粘性。上游把条目 id、加密推理内容和 `previous_response_id` 都存在单个资源下，轮换后重放历史会落到一个从未创建过这些条目的资源上，整轮请求被拒：`The requested item was created under a different Azure OpenAI resource.`

本版在转发 Responses-to-Responses 请求前做一次净化：丢掉每个输入条目的 `id`、所有 `encrypted*` 字段，以及顶层的 `previous_response_id`，让池内任意资源都能接住这份无状态请求。纯 `item_reference` 条目整体丢弃，因为留下它却不带 id 只会把跨资源错误换成缺参数错误。消息正文、工具调用 id 与参数、摘要、请求头和响应流都不动。

- 开关在账号 → 高级选项：`responses_cross_resource_strip`（自动 / 开 / 关），默认「自动」，内置 `agentrouter.org`、`ps.air-outer.com` 两个地址默认开启。
- 该净化跑在既有的推理内容清理之前；推理清理的保守模式会刻意保留格式正确的密文（正是这个报错包含的东西），激进模式也只覆盖 `type: "reasoning"` 条目，所以两者不能互相替代。
- 代价：模型每轮重新推理，不再延续隐藏的思维链；只回传 `previous_response_id` 的客户端会丢掉服务端上下文。

## 改进：客户端接入页重做，去掉误导性的平台 tab

`v0.1.3` 的 `Codex / Claude / Gemini / Grok` 四个 tab 是**客户端协议族**，不是账号池平台；但标签和文案让页面看起来像回到了已经删掉的平台层级。本版把接入页整体重做：

- 现在是一张统一卡片列表（宽屏两列）= 原 Codex 客户端 + Claude Code。账号池始终只有一个（后端池身份恒为 `codex`），不需要先选平台。
- 每张卡片标注**接口格式**：Codex CLI 为 `Responses`，Claude Code 为 `Messages`，其余第三方 Agent 默认 `Chat`。写入时按格式自动分组，调用各自的适配器与该格式的接入 Key，用户不用手动挑。
- 第三方 Agent 没有可再分发的官方图标源，改用确定性的品牌色字母标识；两个一方 CLI 仍是原品牌 SVG，插件保持完全离线。
- 删掉了「每个平台的算力池端点 API Key 都不一样……切换平台后要各自复制」这句在统一账号池下已经不成立的旧文案。手动配置说明改为：展示的是主 `codex` 族的 Key，写入时会自动为每个客户端填上它自己的 Key。

## 改进：模型清单默认「路由模式」

原「精确模式」改名为「路由模式」，排在第一位并成为新建账号池的默认。

- 路由模式下每个 API 账号各自列出「账号/模型」并把请求钉在该账号上。需要同名模型在池内轮换时切回「聚合模式」（裸别名）。
- 注意这与之前不同：新建池默认不再轮换同名模型，默认的「续写失败换号」也因此不会换账号。**已经按旧裸别名配置过客户端的用户，需要重新写一次配置**；切回聚合模式即可恢复轮换。
- 数据库里已经保存过 `aggregate` 的账号池不受影响。

## 新增：Claude Code 槽位映射弹窗

Claude Code 只有固定的 `/model` 槽位，不能像其它 Agent 那样自由扩展。卡片上的「设置」会打开一个弹窗，按行配置角色、模型 id、显示名与 1M 标记，另有 Subagent 与 Fallback 两行。

- 未改动的行保持「自动」，继续跟随池内账号映射的共识。
- 覆盖值按**模型模式分别保存**：路由模式的模型 id 带账号前缀、聚合模式是裸别名，两者不能共用一份映射。
- 行结构参考了统一账号池后已不可达的旧 Claude 平台账号角色表单。

## 分平台安装包

市场仍为分平台包模式（`packageMode=1`）。Release 同时提供三个包，每个只包含**该平台自己的一个** native 库：

- `otools-ai-switch-0.1.4-windows.oplg`（Windows x64）
- `otools-ai-switch-0.1.4-linux.oplg`（Linux x64）
- `otools-ai-switch-0.1.4-macos.oplg`（macOS ARM64；Intel Mac 暂不提供）

OTools 客户端按当前平台优先下载对应包，下载失败才回退到不带后缀的 `otools-ai-switch-0.1.4.oplg`。CI 打包时强制校验每个平台包只含一个 native 库。macOS 目前只有 ARM64 构建。

## 安装与数据

在 OTools 插件管理中安装/更新对应平台的 `.oplg`，或使用市场自动分发。请使用附带的 `SHA256SUMS` 校验下载文件。

数据库仍保存在 `~/.otools/local/otools-ai-switch/ai-switch.db`，更新不改存储目录或历史 SQL 迁移。本次新增的 `claude_slot_overrides_json` 是可选设置项，旧配置无需改动，不涉及数据库迁移。
