AI Switch · AI本地网关 `v0.1.2`。本次发布安装包适用于 **Windows x64**。

## 升级前必读：AI 接口端口变更

本地 AI 接口默认端口由 `10888` 改为 **`29527`**，默认地址变为 `http://127.0.0.1:29527`。

升级后，之前由插件写入过客户端配置的 Codex / Claude Code / Gemini CLI 等工具，以及任何手工填写的 Base URL，仍可能指向旧的 `10888`。请在账号池工具栏重新写入客户端配置，或把配置里的地址手工改成 `29527`。端口被占用时会明确报错，不会自动换端口。数据库、账号和用量记录不受影响，也不涉及 SQL 迁移。

## 新增与修复

- 修复上游返回 HTTP 200 却在 SSE 流里先发 `response.created`、随后发 `response.failed` 时请求直接失败、没有自动重试的问题。代理现在会短暂等待建流帧，在首个字节透传给客户端之前收到失败帧仍可走原有重试与故障转移流程；已开始输出内容的流不会被重试，避免重复内容。
- 失败重试次数改为**按错误类别分别设置**。账号「高级选项 → 故障处理」页重排为通用重试、按错误类型、账号状态与冷却、流式断流与账号切换、判定规则五组。可分别为网络连接/超时、上游 5xx/408、限流 429、容量不足/高负载、其它响应内错误设置额外重试次数；留空即跟随通用次数（0-10），单类最高可设 **1000 次**，因此「容量不足重试 100 次以上」不再被旧的上限 10 卡住。
- 「容量不足 / 高负载」识别 `no_capacity`、`high demand`、`overloaded` 等上游信号，包含 `too_many_requests` 外壳但 `code = no_capacity` 的情况，并优先于普通账号限流判定。该类可单独设置重试间隔，避免用默认 200 毫秒连续打爆上游；还可设置整次请求的重试总时长上限（0 表示只按次数限制）。
- 容量类失败重试耗尽后**不再把账号记为异常**：不累计临时失败次数、不触发冷却。上游暂时没余量不等于账号坏了，排完 100 次队再把健康账号停掉与「等上游有余量」的目标相反。
- 高级选项新增「容量类一键设为 100 次 / 5 秒间隔」快捷操作，并明确标注手动「模型测试」仍只使用通用次数、不套用按类别策略（诊断请求需要快速失败）。旧账号配置无需改动，未填写的新字段一律沿用原有行为。

## 安装与数据

在 OTools 插件管理中安装/更新 `otools-ai-switch-0.1.2.oplg`。请使用附带的 `SHA256SUMS` 校验下载文件。

数据库仍保存在 `~/.otools/local/otools-ai-switch/ai-switch.db`，更新不改存储目录或历史 SQL 迁移。桌面宿主重启后由后台任务启动 AI 服务；纯 CLI 自动启动未包含在本次实现中。

## 验证范围

发布前验证：前端 **861 项测试通过**（75 个测试文件），类型检查与生产构建通过；Rust **1955 项单元测试通过**，6 项需要真实账号/环境的测试保持忽略。新增回归覆盖：`response.created → response.failed` 自动重试、按分类 100 次容量重试、其它语义错误不受容量类放宽影响、容量类失败不惩罚账号、错误分类词表不误伤上下文长度与额度错误。最终 Windows release 库另外执行隔离烟测、后台跨进程重启测试及生图路由本地模拟测试。

按错误类别重试不提供字面意义上的无限重试，上限为 1000 次并可叠加总时长上限。开启「失败后切换到池内其它账号」时，换号后重试计数归零，需要整次请求封顶请设置总时长上限。macOS/Linux 安装包、真实账号 OAuth、付费生成及实际 OTools 宿主安装端到端验收未作为本次已验证结果。
