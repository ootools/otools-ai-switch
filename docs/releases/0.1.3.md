AI Switch · AI本地网关 `v0.1.3`。继续提供 **Windows x64 / Linux x64 / macOS ARM64** 三个分平台安装包，每个包只包含该平台自己的 native 库。默认地址仍是 `http://127.0.0.1:29527`，从 `0.1.2` 升级不需要改客户端配置。

## 重点：HTTP 200 流内失败不再「一次就停」

`v0.1.2` 发布后仍有实测反馈：上游先发 `response.created`，十几秒后才发 `event: response.failed`（`code: rate_limit_exceeded` / "exceeded token rate limit"），请求直接停止、没有重试。定位到四个叠加原因，本版全部修复：

1. 固定 3 秒的建流等待窗口太短，迟到的失败帧落到了「响应已提交」之后。
2. 区域级 token 吞吐限流被归到普通 `RateLimit`，没用上给「容量不足」配置的长重试预算。
3. 流首失败统一等固定 500 毫秒，容量类没走自己配置的间隔。
4. 真实的 `response.created` 会回显完整请求（system prompt + 工具 schema），单帧可能超过 64 KB 或被拆成多个网络块；半截 `data:` 行被误当成正文，提前提交响应。

现在提供**可配置的建流等待窗口**（默认 60 秒，最大 10 分钟，`0` 恢复即时提交），并把「容量不足 / 高负载」的识别扩到 `no_capacity`、`high demand`、`overloaded` 与区域级 token throughput 限流。账号配额、固定窗口限流仍归「限流 429」，不会被误判成容量问题无限重试。容量类耗尽重试后依旧不累计账号故障、不触发冷却。

## 新增：流内失败自动救回（默认关闭）

正文已经发给客户端后再报的流内失败无法回滚重试。本版复用已有断流续写管线，为这类情况补上第三阶段处理：网关扣住失败帧，用「原会话 + 已写出的半截回答」再问一次，把答案接回同一条响应，客户端看到的是一条连续的 SSE。

- 开关：账号 → 高级选项 → 故障处理 → **④ 流式断流与账号切换 → 流内失败时自动救回**。
- 只接上游侧瞬时失败：容量不足、区域级 token rate limit、普通限流、上游 5xx。额度耗尽、内容审核、上下文超长、图片过多、权限不足这类硬判决永远原样透传。
- 次数取「② 按错误类型单独设置」里该类别的上限，间隔走该类别的专用间隔；整次请求的总时长上限同样生效，100 轮容量预算不会绕过用户设的时间封顶。救回预算耗尽或无法续写时，被扣住的失败帧原样补发，不会合成一条假的 `response.completed`。
- 默认关闭：每轮救回都是一次完整计费请求，客户端拿到的是模型分多次写成的答案，聚合模式下还可能换号；成功救回的请求不再把账号记成故障。仅对 Responses 协议生效，纯 Chat `messages` 请求没有可重建的 `input` 数组，无法续写。

三个阶段合起来：输出尚未发出且在建流等待窗口内 → 直接回滚重试；正文已发出且开启救回 → 扣住失败帧续写接完；两者都不满足 → 透传失败帧。「故障处理」里的判定规则说明已同步更新。

## 其它

- 手动「模型测试」仍只使用通用重试次数，不套用按类别策略，也不触发救回。
- 所有新字段都在 `failure_policy`（`route_credentials.config_json`）里，旧账号配置无需改动，不涉及数据库迁移。

## 分平台安装包

市场仍为分平台包模式（`packageMode=1`）。Release 同时提供三个包，每个只包含**该平台自己的一个** native 库：

- `otools-ai-switch-0.1.3-windows.oplg`（Windows x64）
- `otools-ai-switch-0.1.3-linux.oplg`（Linux x64）
- `otools-ai-switch-0.1.3-macos.oplg`（macOS ARM64；Intel Mac 暂不提供）

OTools 客户端按当前平台优先下载对应包，下载失败才回退到不带后缀的 `otools-ai-switch-0.1.3.oplg`。CI 打包时强制校验每个平台包只含一个 native 库。macOS 目前只有 ARM64 构建。

## 安装与数据

在 OTools 插件管理中安装/更新对应平台的 `.oplg`，或使用市场自动分发。请使用附带的 `SHA256SUMS` 校验下载文件。

数据库仍保存在 `~/.otools/local/otools-ai-switch/ai-switch.db`，更新不改存储目录或历史 SQL 迁移。桌面宿主重启后由后台任务启动 AI 服务；纯 CLI 自动启动未包含在本次实现中。

## 验证范围

发布前验证：Rust **1975 项单元测试通过**、6 项需要真实账号/环境的测试保持忽略；前端 **75 个测试文件、865 项测试通过**，`tsc --noEmit` 与生产构建通过。新增回归覆盖：迟到失败帧跨过旧 3 秒窗口、70 KB 建流回显（整帧与 9 KB 分块）、完整回显后接拆分失败帧、区域吞吐限流归入容量预算、正文已输出后的流内救回（换号续写、单一 `response.created`、补收尾、不惩罚账号）、开关默认关闭、额度硬判决不救回、预算耗尽补发失败帧且不合成假完成、总时长上限管住救回、各类别分类词表带与不带 `event:` 行。

按错误类别重试不提供字面意义上的无限重试，上限为 1000 次并可叠加总时长上限。开启「失败后切换到池内其它账号」时，换号后重试计数归零，需要整次请求封顶请设置总时长上限。macOS/Linux 安装包、真实账号 OAuth、付费生成及实际 OTools 宿主安装端到端验收未作为本次已验证结果。
